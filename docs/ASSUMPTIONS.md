# 잠정 결정 사항 — 확정되면 화면을 고쳐야 하는 것들

> `npm run assumptions` 로 자동 생성. 원본은 `src/data/assumptions.ts`.

목업을 실제 제품처럼 보이게 만들려면 아직 확정되지 않은 항목도 일단 그려야 합니다.
그렇게 **임의로 정한 것**을 여기에 모았습니다. 화면에는 표시하지 않습니다.

**21개 화면 · 30건**

> ⚠ 아래 항목은 전부 "확정되면 화면을 고쳐야 하는" 것들입니다.
> 데모에서 보이는 수치·명칭·코드값을 확정 사항으로 오해하지 마세요.

## 화면별 상세

### `F-4.1-2` 상벌점 관리

Phase 1 · MVP · 화면 경로 `/s/student-penalty`

- **임의 결정** 상벌점 자동 부여 트리거 8종(ATTENDANCE_LATE, ROUTINE_INCOMPLETE 등)과 배점을 임의 지정
  - 확정 시 → PenaltyRuleEngine 매핑 규칙이 확정되면 트리거·배점 전면 교체. 현재 동작은 수기 부여만
  - 관련 이슈 `I-5`
- **임의 결정** 학생 노출 명칭을 '상벌점' 그대로 사용
  - 확정 시 → 완화 명칭(관리점수/나의점수 등) 확정 시 라벨 일괄 변경

### `F-4.1-5` 사유 신청 관리

Phase 1 · MVP · 화면 경로 `/s/student-absence`

- **임의 결정** 항목별 승인 주체(결석=학부모, 지각=담임 등)와 응답 제한시간(30~240분)을 임의 배정
  - 확정 시 → 승인 주체 매트릭스 확정 시 전면 교체
  - 관련 이슈 `I-12`
- **임의 결정** '벌점 확정 후 사유 승인 불가' 기준이 없어 승인 버튼을 항상 활성으로 둠
  - 확정 시 → 기준 확정 시 조건부 비활성 처리 추가
  - 관련 이슈 `I-10`

### `F-4.2` 대기자 관리

  - 관련 이슈 `D-7 / S-1`

### `F-4.3` 출결 관리

Phase 1 · MVP · 화면 경로 `/s/attendance`

  - 확정 시 → 실제 payload 포맷 수령 시 수신부 교체. 상태 enum도 대성전산 정의에 맞춰 재정의될 수 있음
  - 관련 이슈 `D-2`
- **임의 결정** 순공시간을 단순 재실시간으로 계산
  - 확정 시 → 입퇴실·좌석없음 차감 규칙 확정 시 산출식 교체
  - 관련 이슈 `I-6`

### `F-4.4` 문자 발송 → 카카오톡 발송(문자 병행)

  - 확정 시 → 심사 결과에 따라 FCM 단독으로 바뀔 수 있음. 문구는 운영팀 확정본으로 전량 교체
  - 관련 이슈 `E-5 / I-4 / I-14`

### `F-4.5` 급식 관리(디멤버 급식신청 대체)
