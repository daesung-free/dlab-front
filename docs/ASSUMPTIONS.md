# 잠정 결정 사항 — 확정되면 화면을 고쳐야 하는 것들

> `npm run assumptions` 로 자동 생성. 원본은 `src/data/assumptions.ts`.

목업을 실제 제품처럼 보이게 만들려면 아직 확정되지 않은 항목도 일단 그려야 합니다.
그렇게 **임의로 정한 것**을 여기에 모았습니다. 화면에는 표시하지 않습니다.

**31개 화면 · 70건**

> ⚠ 아래 항목은 전부 "확정되면 화면을 고쳐야 하는" 것들입니다.
> 데모에서 보이는 수치·명칭·코드값을 확정 사항으로 오해하지 마세요.

## 화면별 상세

### `F-4.1-2` 상벌점 관리

Phase 1 · MVP · 화면 경로 `/s/student-penalty`

- **임의 결정** 상벌점 자동 부여 트리거 8종(ATTENDANCE_LATE, ROUTINE_INCOMPLETE 등)과 배점을 임의 지정

  - 관련 이슈 `I-5`
- **임의 결정** 학생 노출 명칭을 '상벌점' 그대로 사용
  - 확정 시 → 완화 명칭(관리점수/나의점수 등) 확정 시 라벨 일괄 변경

### `F-4.4` 알림 발송 (알림톡 · 푸시)

  - 확정 시 → 운영팀 확정본으로 전량 교체. 코드는 발송 API가 참조하므로 확정 후 변경 금지
  - 관련 이슈 `I-4 / I-14`
- **임의 결정** SMS 제외 결정에 따라, 자유 문안을 FCM 푸시 전용으로 두고 앱 미설치자에게는 발송 수단이 없는 상태로 그림
  - 확정 시 → ⚠ 운영 확인 필요 — 앱 미설치 학생·학부모에게 템플릿에 없는 내용을 전달할 방법이 현재 없다. 공지성 문안을 템플릿으로 사전 등록하는 운영으로 갈지, SMS를 되살릴지 결정해야 함
  - 관련 이슈 `E-5`
- **임의 결정** 알림톡 심사 상태 4종(승인/심사대기/반려/해당없음)을 자체 정의하고 미승인 시 발송 버튼을 비활성 처리
  - 확정 시 → 카카오 심사 응답 규격 확인 시 상태값·재제출 플로우 교체
  - 관련 이슈 `E-5`

### `F-4.5` 급식 관리(디멤버 급식신청 대체)

Phase 2 · 핵심 · 화면 경로 `/s/meal`

- **임의 결정** 1식 6,500원, 가상계좌 만료 10분 주기, 전표번호 형식 MO-YYYYMM-NNNN 을 임의 지정
  - 확정 시 → PG 연동정보 수령 시 전표 체계·정산주기 재설계
  - 관련 이슈 `E-3 / E-4`
- **임의 결정** 데스크 당일 신청의 결제·환불 주체를 관리자 즉시 처리로 가정
  - 확정 시 → 결제 방식(PG카드/현금/수납)과 환불 주체 확정 시 흐름 변경
  - 관련 이슈 `I-13`
- **임의 결정** 급식 중단 사유 5종(학원 휴무 / 급식업체 휴무 / 단축수업 / 모의고사 / 자체 행사)과 신청 마감 D-3, 월 접수기간을 자체 제안
  - 확정 시 → 운영팀 확정 시 교체. 사유 목록은 기초관리 마스터로 이관될 수 있음
- **임의 결정** 이미 결제된 날을 중단 처리할 때 전액 환불로 가정하고, 서버가 (결제건 확인 → 환불 배치 → 중단 확정) 순으로 처리한다고 그림
  - 확정 시 → ⚠ 부분 환불·급식업체 위약 조건 확인 필요. 업체에 이미 식수를 통보한 뒤 중단하면 환불 불가 구간이 생길 수 있음
  - 관련 이슈 `E-4`
- **임의 결정** 배식 체크 주체를 학생 본인(앱 QR 태깅)으로 잡고 관리자는 확인·입회 역할로 그림
  - 확정 시 → ⚠ 요구사항정의서 0723 메모("식사체크 주체 = 관리자, 학생 아님")와 상충한다. 운영 확인 결과를 반영한 것이므로 I-18 종결 시 메모를 운영 기준으로 정정해야 함
  - 관련 이슈 `I-18`
- **임의 결정** 태깅 결과 5종(OK/MANUAL/DUP/NOORDER/FAIL), 실패 사유 5종, 배식시간 11:50~13:10을 임의 정의
  - 확정 시 → 단말 구성·인식 규격 확정 시 교체. 안면·지문 채택 시 개인정보/ISMS 검토 선행
  - 관련 이슈 `I-18 / D-2`
- **임의 결정** QR을 30초 회전 1회용 토큰으로 전제 (정적 QR 금지)
  - 확정 시 → 앱 개발과 함께 토큰 수명·오프라인 대비 방식 확정. 만료가 짧으면 네트워크 지연 시 실패가 늘어 수기 확인 비중이 커진다
  - 관련 이슈 `I-18`
- **임의 결정** 수기 확인을 예외가 아닌 정상 경로로 두고, 관리자가 즉시 통과시킨 뒤 사유·확인자를 남기도록 설계
  - 확정 시 → ⚠ 수기 확인 권한을 누구까지 줄지(담임/행정/배식 담당) 미정. 남용 방지를 위한 사후 점검 절차도 필요
- **임의 결정** 신청했으나 미태깅인 건을 "미체크"로 남기고 환불 검토 대상으로만 표시
  - 확정 시 → ⚠ 미체크분 환불 여부는 정책 미정 — 자동 환불인지, 실적 집계용으로만 쓰는지 확정 필요
