### 1-1 특강 상세 모달 — 가장 먼저

들어갈 입구만 만들면 막혀 있던 수정·삭제·차수·출석부가 한꺼번에 열린다.

```
PATCH  /lectures/{id}                    수정      ← 호출 코드 있음, 진입점 없음
PUT    /lectures/{id}/status             상태
PUT    /lectures/{id}/visible            노출
POST   /lectures/{id}/sessions           차수 추가
GET    /lectures/{id}/attendance-targets 출석 대상
GET/PUT /lectures/sessions/{id}/attendances  차수별 출결
```

**단건 조회 API 는 필요 없다**(2026-09-14 확인). `GET /lectures` 목록 응답이 상세를 다 내려준다 —
설명·정원·금액·기간·신청기간·담당교사·분류·확정/대기 인원까지. **모달은 목록에서 받은 값으로 채운다.**

### 1-7 상벌점 — 서버는 다 있다

```
GET/POST/PUT/DELETE /penalty-items        항목      ?year= 필수
GET/POST/PUT/DELETE /penalty-rules        자동 부여 규칙 (+ /{id}/active 토글)
POST   /penalties                         수동 부여
DELETE /penalties/{id}                    취소
```

**"자동 부여분을 사람이 조정"은 서버로 이미 된다.** 화면만 없다.

### 1-2 수납 청구 생성

```
POST /tuition/billings/monthly     월 청구
POST /tuition/billings/admission   입학금
POST /billings                     청구 생성
POST /billings/{id}/payments       수납 처리
DELETE /billings/{id}              청구 취소
DELETE /billings/payments/{id}     수납 취소
```

⚠ **청구를 자동 생성할지 직원이 만들지가 클라이언트 회신 대기 중이다.**
어느 쪽이든 위 API 는 붙어야 하므로 **직원이 만드는 쪽부터** 붙이고 자동 생성은 나중에 얹는다.

✅ **09-14 직원 생성분 완료.** 수납현황(F-4.8) 통합 매출장에 붙였다.
청구 등록(교습비 월 / 그 밖) · 수납 · 청구 취소. 회신이 오면 여기에 자동 발행을 얹는다.
`POST /tuition/billings/admission`(입학금)은 아직 안 붙였다 — 신규 접수 등록 흐름에
들어가야 자연스러운데 그건 1-3 과 묶여 있다.

## Phase 2 — 화면이 아예 없는 것

기초 관리에 탭을 더하는 것과, 화면을 새로 만드는 것으로 갈린다.
**11개 모두 요구사항정의서 36개 화면에 없다 — 목업 수정 승인이 필요하다.**

### 2-A. 기초 관리 탭 추가 ✅ 2026-09-16 완료

장학 종류·상벌점 항목이 이미 그 화면(`BasicSettings.tsx`)에 탭으로 들어가 있다.
같은 모양으로 붙인다 — **화면을 새로 만들지 않아 메뉴가 안 늘어난다.**

2026-09-16 실호출로 네 곳 모두 서버·데이터 확인:

```
/seats/areas?academyId=8              2건
/periods?academyId=8&year=2026       34건  (오픈시간 · 1교시 · 점심식사 …)
/absence-categories?academyId=8       5건  (병결 · 가정사 · 학교 행사 …)
/consults/tags?academyId=8&year=2026  0건  (서버는 있고 데이터만 없음)
```

★ `year` · `academyId` 가 **필수**인 것이 섞여 있다. 안 보내면 400 이다.

#### 2-1 은 구역만 만들면 안 된다

구역을 만들면 `seatCount: 0` 이라 배치도가 빈 채로 남는다. 등록 폼에서 행·열을 함께 받아
두 호출을 이어 준다 — `grid` 가 그래서 있다.

```
구역 등록 (이름 · 코드 · 5행 × 8열)
   → POST /seats/areas          구역 생성
   → POST /seats/masters/grid   좌석 40개 자동 생성
```

- 좌석에는 **x·y 좌표**가 필요하다. 배치도를 그리는 근거이고 없으면 화면이 빈다
- 고장·공사로 못 쓰는 자리는 삭제가 아니라 **`PATCH /seats/{id}/usable` 로 사용중지**한다.
  지우면 배치도에 구멍이 생긴다

#### 2-11 반 좌석표 — 서버부터 없다

```
ClassMaster    지점 · 연도 · 이름 · 반 유형 · 정원          ← 좌석 관련 필드 없음
SeatMaster     지점 · 자습구역 · 좌석코드 · x · y · 사용가능  ← 반 참조 없음

좌석이 **자습 구역에만** 속하는 구조다. 강의실(`/masters/rooms`)에도 좌석 개념이 없다.

| 단계 | 담당 |
|---|---|
| 설계 — 별도 테이블로 둘지, `SeatMaster` 에 반 구분을 더할지 | BE |

**독서실 구조를 그대로 따르는 것이 낫다.** 그리드 일괄 생성까지 만들어져 있으니 같은 모양이면
2-1 화면을 재사용할 수 있다.

#### 2-10 와이파이 해제 — 관리자 처리 경로가 없다 (2026-09-16 재확인)

앱에서 **신청만** 된다. 그걸 조회·승인·거절할 관리자 API 가 없다.

```
POST /api/v1/app/firewall/requests        와이파이 해제 신청 (A-8)   ← 앱. 이것뿐이다
PATCH /admin/branch-configs/{id}/nebula-device-id   장비 ID 변경     ← 방화벽 장비 설정(2-6)
```

스펙 설명에 "신청하면 **학부모와 담당선생님에게 동시에** 알림이 간다"고 적혀 있으니
승인받을 사람은 정해져 있는데, **그 사람이 쓸 화면의 API 가 없다.**

| 단계 | 담당 |
|---|---|
| 신청 목록 조회 · 승인 · 거절 API | BE |
| 처리 화면 | FE |

승인 주체(학부모 우선 / 담임 자율) 설정은 2-6 에 붙인다 — 0914 내부 결정 사항이다.

⚠ 2-6 · 2-7 은 **클라이언트 확인 대기**다(가맹점 코드 등록 방식 · 지점별 업체 배정).
답이 오기 전에는 착수하지 않는다.

### 2-12 단말기 결제 (F-C-5) — 2026-09-16 경로 확정, 착수 전

결제 관리는 "PG 미연동" 으로 목업이었는데 **단말기 결제 경로가 정해졌다.**
승인은 **화면이 단말에 직접** 요청하고 서버는 기록만 한다 — 서버가 다시 요청하면
이중 승인이다. **저장 실패를 '결제 실패'로 쓰면 이중 결제가 난다.**

계약과 주의점은 `docs/API_GAPS.md` 25부에 적어 뒀다. **붙이기 전에 그것부터 읽는다.**

## Phase 3 — 서버가 먼저 필요한 것

**설계·테이블·API 부터 필요하다. 화면은 그 뒤에 붙인다.**

| # | 항목 | 담당 | 내용 |
|---|---|---|---|
| 3-1 | **조회 전용 계정별 메뉴 노출** | BE→FE | 역할 단위가 아니라 **계정 단위**로 최고관리자가 고른다. 화면만 감추는 게 아니라 **서버 권한 판단도 이 설정을 따라야** 한다 |
| 3-2 | 직원 계정 잠금 해제 | BE | 앱 계정만 경로가 있다. 직원이 5회 틀리면 **DB 를 건드리지 않는 한 못 푼다** |
| 3-3 | 자주 쓰는 메뉴 관리 | BE→FE | 대시보드 좌측이 코드에 박힌 배열이다. 계정별로 고를 수 있어야 한다 |

### 지금 권한은 어디까지 막혀 있나

3-1 이 오기 전까지의 상태다.

- **관리자 그룹** — 메뉴 숨김 + 주소 직접 진입 차단 (`/g/admin` · `/s/admin-*`)
- **조회 전용** — API 클라이언트에서 GET 아닌 요청을 끊는다
- 그 밖의 역할(담임이 상벌점을 줄 수 있는가 등)은 **손대지 않았다.** 추측이 되기 때문이다

### 시드

`2026-0001 서도윤` 이 상태 변경 확인 중 퇴원 처리됐다. `WITHDRAWN → ENROLLED` 가 설계상

```

**클라이언트에게 링크를 주기 전에 다시 넣는 쪽을 권한다.** 학번이 튀면 질문이 나온다.
